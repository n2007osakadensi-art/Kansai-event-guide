# 試作サイトの編集機能 仕様（2026-11-23、Kota着工指示）

## 目的
スペース版ガイドの「更新・修正・新規登録」と同じことを、試作サイト（GitHub Pages）からもできるようにする。サービス乗り換え準備の一環（スペース基盤に依存しない編集経路を持つ）。

## 大前提（2026-11-23 15:53 Kota）
- 基本の編集はスペース版から行う。試作サイトの編集は「同じことができる経路」を持つことが目的で、運用の主従は変えない。

## 方式：ステージング経由（直接掲載にはしない）
- 試作サイトのフォーム送信 → Apps Scriptゲートウェイ → シートの「編集入力」タブに蓄積 → 確認のうえスペース版ガイドへ登録・反映（外部AI入力タブと同じ取り込み思想）。
- 理由：シートの events タブはガイド同期（write_sheets.py）が全件上書きするため、サイトから直接書いても次の同期で消える。正本はスペース版ガイドのままにする。
- ゲートウェイはシートに紐づく Apps Script（doPost）。デプロイとURL発行はシート所有者（Kota）の作業で、URLは editor-config.js に入れる。

## フォーム項目（スペース版の登録項目に合わせる）
種別（新規/修正）、対象イベントID（修正時）、タイトル、日付、終了日、時刻ラベル、会場、府県、エリア、カテゴリ、出演者（複数行）、タイムテーブル（複数行・自由記述、取り込み時に構造化）、料金、料金区分（無料/有料/一部無料/不明）、主催、公式リンク、チケットリンク、画像URL（複数行）、説明、備考、提出者（会員acctがあれば自動付記）。

## 入口の位置（Kota、2026-11-23 16:44／16:49改定）
- ヘッダー（「ログイン / 同期」の隣）に「＋ 新規登録・修正」ボタンを出す。スペース版と同じく、メイン画面から直接開ける位置にする（ダイアログの奥に埋めない）。
- 当初は管理者モードの端末だけに表示する形にしたが、Kotaが確認できなかったため常時表示に改めた（2026-11-23 16:49）。送信は受付タブへの申請形式で、誰の送信も掲載に直接は影響しないため、常時表示で問題ない。管理者モードは提出者ラベル（admin）とアンケート抑止のためだけに残る。

## 段階
- 第1段階（着工済み）：フォームUI、ゲートウェイ（Apps Script）、編集入力タブへの蓄積、未設定時の明示。
- 第2段階：取り込みの自動化（編集入力タブ → 一次ソース確認 → ガイド登録 → 状態記録）。外部AI入力の夜間ジョブと同じ枠組みに載せる。
- 第3段階：アーティスト/会場プロフィールの登録・修正も同じ経路へ。

## 制約・未検証
- 反映は即時ではない（取り込み＋シート同期＋gvizキャッシュの遅延がある）。
- 画像はURL取り込みのみ（端末からの画像アップロードはApps Script経由では扱わない）。
- ゲートウェイURLを知る者は送信できるため、掲載前の確認（ステージング）が前提。荒らし送信はタブ側で未処理のまま捨てられる。
