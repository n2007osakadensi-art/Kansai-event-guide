## 実装（試作サイト、SW v39）
### 1. アーティストカテゴリの統一
- assets/artist-cats.json（名前→カテゴリ、2,930件）を新設し、プロフィールと一緒に遅延読み込みする。
- 解決関数 artistCategoryOf(name) を唯一の入口にする。順序:
  (a) プロフィールのカテゴリ（artistProfileFor 経由、別名解決込み）
  (b) artist-cats の完全一致
  (c) 検索辞書で正式名に解決してから (a)(b)
  (d) メンバーなら所属グループの解決結果
  (e) どれにも無ければ未分類（推測で入れない）
- チップ・件数・一覧の表示・詳細画面のカテゴリ表示はすべてこの関数の結果だけを使う。
  イベントカテゴリ由来の寄せ集めは廃止。チップは全カテゴリ（件数順）＋ユニドル常時表示（従来仕様）
  ＋最後尾に『未分類・要確認』（件数つき）。チップ件数と実表示件数を一致させる。

### 2. 会場DBの絞り込み再設計
- イベント側の内容条件との連動を廃止する（会場DBは独立に動く）。
- ジャンル階層（4グループ）を主軸から外す。主タブ = 都道府県:
  すべて / 大阪府 / 京都府 / 兵庫県 / 滋賀県 / 奈良県 / 和歌山県 / その他・未設定（各件数つき）。
  都道府県の決め方: 掲載イベントから得た府県 → プロフィール住所の府県接頭辞 → いずれも無ければ
  その他・未設定（落とさない）。
- 都道府県を選ぶと、その府県のエリア（掲載イベントのエリア語彙）のチップを出す（簡単なエリア分け）。
- 副次フィルタとして種別チップを1行だけ残す: 種別 = プロフィールの genre、無ければ type を正規化して使う。
  イベントカテゴリの語彙は混ぜない。
- キーワード検索と「イベント掲載のある会場のみ」は従来どおり併用可。会場候補サジェストも従来どおり。

### 3. プロフィールの追加・修正・確認（SNS等）
- アーティスト詳細・会場詳細に「プロフィールの追加・修正を送る」ボタンを置く。
- フォーム項目はスペース版の保存項目に合わせる。
  アーティスト: カテゴリ / 公式サイト / X / Instagram / TikTok / 紹介文 / 別名 /
  メンバー（名前・役割・X・Instagram） / 根拠・出典 / 備考。
  会場: 住所 / 自治体 / 種別（ジャンル・施設種別） / 公式サイト / X / Instagram /
  アクセス / 収容人数 / 営業時間 / 紹介文 / 根拠・出典 / 備考。
- 現在のプロフィール値を初期表示し、直す箇所だけ変えて送る。送信はイベント編集と同じ受付口への
  申請方式（kind=artistProfile / venueProfile）。受付でガイド本体に反映され、プロフィールデータが
  更新されると詳細画面に新しい値が出る（＝確認できる）。未送信の項目で既存値を消さないのは受付側の
  取り込み規律（完全置換の保持）に従う。
- 送信にはイベント編集と同じ25秒の打ち切りと結果表示を使う。
