# 検索の仕組み

関西イベントガイドの検索が「どう動くか」の正本です。検索を直す・改善するときは、まずこの文書で現行の仕組みを確認してください。検索の設計方針（全画面で同じルール・基準）は `docs/site-design-rules.md`、辞書データの項目定義は `docs/data-dictionary.md` が正本です。

## 設計原則

- 検索は「入力した文字列のまま」が原則。入力の自動変換・自動置換・自動分割（スペースで割って複数条件化する等）・自動条件付けはしない
- 候補（サジェスト）は補いであり、検索の意味を変えない。候補を選んでも、同じ文字列を手入力した場合と結果は同じでなければならない
- 検索のルール・基準は全ての面（本体／試作／フィード／ミラー）で同一にする。確定挙動の基準はスペース版ガイド（本体）で、公開面はそれに合わせる。面によって結果が違う状態は不具合
- 表記ゆれへの対応は、利用者の入力を書き換えるのではなく、登録側（辞書・別名）を厚くすることで行う。OSの予測変換には期待しない（固有名詞・英字混じりの公式表記は予測変換では出てこないため）

## 照合の仕組み（試作サイトの実装）

- 照合は正規化した1文字列同士の部分一致のみ。正規化（normSearch）の内容: 半角カナ→ひらがな、全角英数字→半角、英字は小文字化、カタカナ→ひらがな、小書き仮名（ぁゃっ等）を通常の仮名へ、中点（・･）を除去
- 検索対象の文字列（searchHay）はイベントごとに組み立てる: タイトル／会場／会場スペース／出演者／カテゴリ／エリア／府県／主催者名／日付（表記バリエーション込み）。さらに説明文のタイムテーブル行、出演者の読み・プロフィールの別名・辞書の語、グループの場合はメンバー名、タイトルと会場の辞書の語、会場プロフィールの正式名・別名・住所（表記バリエーション込み）まで含める
- 詳細データの統合が終わる前は出演者が検索対象に入らない（読み込みの2段構えのため）。統合完了後に検索し直すのが前提

## 辞書の統合

- 検索辞書はシートの「検索辞書」タブから実行時に読み込み、本体の辞書と統合する。辞書の語は、対象（出演者・タイトル・会場）の検索対象文字列に自動で含まれる
- 辞書の種別には、対象ごとの別表記・読み・略称のほか、イベント名の辞書と単語の辞書があり、組み合わせでの照合も行う（例: 「ラーメンエキスポ」で「ラーメンEXPO」に当たるのはこの仕組み。2026-11-24 に追加・実証済み）
- プロフィールの別名（エイリアス）も検索対象に入る。本体の名前は現行の公式表記のみで、旧名・表記ゆれは別名と辞書の側に置く

## 入力経路のパリティ

- 手入力、サジェストからの選択、URL（チケット販売ページ）からの検索で、絞り込み条件（期間フィルタ・終了分の扱い等）は同一でなければならない
- 過去の不具合（2026-11-25 v103 で修正・検証済み）: サジェスト選択時だけ終了分の除外と期間フィルタの適用が手入力と食い違い、同じ探し方で違う結果になっていた。経路ごとに条件を二重に持つ実装が原因。条件は1か所で適用する

## サジェスト（候補）

- 候補は辞書・タイトル・出演者・会場等から出す補いであり、候補の有無が素の検索結果を左右してはならない
- ジャンルの提案や行き先（会場・エリア）の候補表示は検索とは別の補いであり、検索が有効な間はおすすめ・ジャンル提案・アンケート導線を隠す設計とセットで扱う（サイト設計ルール）

## 救済とフォールバック照合

素の部分一致で当たらなかった場合に限り、次の順で救済する。いずれも登録タイトル自体は変えない。

- **終了分の救済**: ヒットが終了したイベントだけのときは、終了分を表示し、その旨を画面に注記する（「検索に当たったのが終了したイベントのみのため、終了分を表示しています」）。終了分を隠したまま「0件」とはしない
- **住所の表記ゆれ**: 数字や市・区・町・丁目・番地を含む入力は、住所の表記ゆれを吸収した形でも照合する
- **簡易検索**: 年号・副題を落としたタイトルキーでも照合する（登録タイトルは正式名称のまま。検索側だけの緩和）
- **話数・回数検索**: 「シリーズ名＋番号」の入力は、タイトル系列と番号で照合する。公式の番号が優先で、公式に番号が無い場合はガイド側の集計（ガイド数え）であることを明示する。入力文字列そのままの照合を先に見るため、番号つきの公式タイトルが話数解釈で潰れることはない。番号だけの書き方も話数照合で拾う

## 推し照合との統一

- 推し（お気に入りアーティスト）の出演判定は、検索と同じ展開（別名・辞書・グループ⇔メンバーの相互展開）で行う（2026-11-25 v104 で統一・検証済み）。検索で当たる出演者が推し表示で当たらない、といった食い違いは不具合として扱う
- 推しごとの絞り込み（そのアーティストが出る公演だけを見る）も同じ照合の上に置く

## 改善の循環

- 検索ログ（解釈できなかった入力を含む）をシートのログ系タブに蓄積し、AIが後から読んで、辞書への語の追加・パターン対応・「もしかして」候補の改善を提案 → 検証 → 反映する循環で改善する
- 対象は広く取る: 誤字脱字のもしかして、間違った日程での検索、表記ゆれ、曖昧な記憶からの検索
- 検索の実行自体はAIなし・トークン0のまま。AIは改善の後段だけに使う

## 既知の課題・過去の教訓

- B-TRIBE のフルタイトル検索で当たらない事例（2026-11-18 報告）: 原因は調査中。再発防止のため、タイトル完全一致の検索は回帰確認の対象にする
- スペース版ガイド側の検索修正（2026-11-20）の画面レベル確認は未検証のまま残っている
- EBiDAN の事例（2026-11-24）: ガイドのサジェストは候補を出しており検索側は正常だった。問題は、運営者の略記「EBIDAN」を Muse が文字列のまま照合して「0件」と誤報したこと。略記は文脈と既存登録から公式表記へ解決してから照合する（手順側のルールであり、検索の仕様ではない）
- 検索候補から選んだイベント名は、そのイベントだけが返らなければならない（候補選択＝その対象の確定として扱う）
