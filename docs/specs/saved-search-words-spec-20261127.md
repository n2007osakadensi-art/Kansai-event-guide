# 検索ワード保存（仮機能）仕様 — 2026-11-27

Kotaの指示（2026-11-27 16:42–16:44）:
- 主催などプロフィール登録が無い対象でも、検索ワードの保存があれば代替機能として役立つ。
- 保存したワードはタイムラインのフォローと同じ場所に表示する（タイムラインのフォロー欄。全体に流れてもよい）。
- タイムラインやカレンダーに反映させる形で考えてよい。当然オンオフ機能ありで。
- 位置づけは、機能や情報登録が整ってくるまでの「仮機能」。

## 設計

### 保存
- 検索ボックスの候補欄の末尾に「＋ この検索ワードを保存（フォローとして追う）」を出す。候補が1件も無い語でも保存行だけは出す（主催名など候補に出ない語が主用途のため）。
- 保存済みの語では「保存済み」の注記に変わる。重複保存はしない（正規化して同一判定）。

### 置き場所（フォローと同じ場所）
- タイムラインのマイページ「フォロー」欄に、アーティスト・会場・主催者に続けて「キーワード」節を置く。フォローの件数表示にも合算する。
- 各行: ワード名、今後の一致件数、反映オン/オフの切替ボタン、✕（保存をやめる）。行のタップで、そのワードの検索結果（イベント一覧）へ移動する。

### 反映（オン/オフ）
- ワードごとに「スケジュール反映」オン/オフ（保存時の初期値はオン）。
- オン のワードは、通常検索と同じ一致（検索用文字列への部分一致）で:
  - タイムラインの「フォロー中」スコープに流れる（followEventSet に合流）。
  - カレンダーの自分の予定では「フォロー中」扱いになる（myCalKinds に合流）。ミックス・フォロー中スコープ・トップの週間帯にもそのまま効く。
- 一致は広い（説明文・タイムテーブル文も対象）ので、広すぎる語は件数表示で気づけるようにし、オフにできる。

### 保存先・同期
- 端末内 localStorage `kg_trial_saved_words_v1`（[{w, on}]）。
- アカウント同期の userdata に `words` を追加（v210 の cals と同じ作り。マージは語の和集合、on はどちらかがオンならオン、上限50件）。

### 範囲外（この便ではやらない）
- フィード側の検索への保存導線（管理は本体タイムラインに集約）。
- マイカレンダーへのキーワード選択肢追加（カレンダー反映は「フォロー中」扱いで足りるため見送り）。
