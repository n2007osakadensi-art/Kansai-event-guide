# 試作サイト SW v65 仕様: 複数画像ギャラリー＋マイカレンダー（2026-11-24）

対象: ~/workspace/guide-repo/ の index.html（必要なら pwa-worker.js の版数と OPERATIONS.md は親が付けるので触らない）。編集後は ~/workspace/guide-unified/ へコピーされる前提で、guide-repo だけを編集すること。

## 1. 複数画像ギャラリー

背景: ガイドには複数画像のイベントが167件ある。公開側は1イベント1URL（シート imageUrl）しか無く、2枚目以降が表示できない。シート形式は変えない（ミラー等への影響回避）。代わりに、複数画像の全URLを持つ静的ファイルをサイトが読み、詳細画面でギャラリー表示する。

- データ: `assets/event-images.json` = { "<eventId>": ["url1", "url2", ...] }（表示順）。このファイルは画像公開バッチ側がマニフェストから生成する。サイト側は「無ければ何もしない」前提で実装する（fetch失敗・404でもエラーにせず、従来表示のまま）。
- 読み込み: loadProfiles と同じタイミング帯で遅延読み込み（初回描画をブロックしない）。読み込めたら window 相当の変数 eventImages に保持。
- 詳細画面（openModal）: そのイベントの画像リスト = eventImages[id] があればそれ、無ければ imageUrl 1枚。2枚以上ある場合のみ、メディア部をスワイプ可能なギャラリーにする:
  - 横スクロールスナップ（scroll-snap）で1枚ずつ切り替わる大きな画像列。下に ●○○ のドット表示と「1/3」のようなカウンタ。
  - タップで従来のライトボックスを開く（開いた画像から）。ライトボックス側は現状の単一画像のままでよい（開いた1枚を拡大表示）。
  - 1枚だけのイベントは従来表示と完全に同じ（余計なUIを出さない）。
- カード・一覧のサムネイルは従来通り1枚目のみ（変更しない）。
- 画像の画質は落とさない（URLそのまま、サイズ指定パラメータを付けない）。

## 2. マイカレンダー

仕様の正本: ~/workspace/goals/goal/hidden_files/timeline-editor-ux-spec-20261124.md の「## F. マイカレンダー」。そこへ今回の拡張を加える:

- 対象スコープ: お気に入り／行きたい／気になる（v62で追加した端末内マーク3種）＋推し出演。この4種を「自分の予定」として月カレンダーに重ねる。
- 場所: 既存カレンダー画面にスコープ切替を追加する（全イベント｜自分の予定）。既存の月移動・スワイプ・日タップの動きはそのまま。
- 表示: 日セルに種別ごとの色ドット（お気に入り=ハート色、行きたい=アクセント色、気になる=橙、推し出演=推し色。既存のCSS変数と v62 の .on 色に合わせる）。同じ日に複数種あれば複数ドット。
- 日タップ: その日の「自分の予定」だけの一覧（種別ラベル付き）を既存の日リスト領域に出す。各行タップで詳細が開く（既存の日リストと同じ動作）。
- 「自分の予定」が0件の月は、空である旨と付け方（詳細でボタンを押す）への短い案内を出す。
- 既存のお気に入り .ics 書き出しは併存（変更しない）。
- 終了したイベントの扱いは既存カレンダーの流儀に合わせる（表示切替に従う）。

## 共通の注意

- 既存機能を壊さない: 通常カレンダー、詳細、サイネージ、タイムライン、絞り込みへの回帰がないこと。
- スマホ幅で横はみ出しを作らない。
- 実装したら node で構文チェックし、結果ファイル（実装内容・変更箇所・自己検証結果・未検証点）を ~/workspace/goals/goal/hidden_files/gallery-mycal-results.md に書く。最終メッセージは短く。
