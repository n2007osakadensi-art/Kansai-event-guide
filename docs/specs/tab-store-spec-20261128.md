# タブストア仕様（2026-11-28、Kota指示）

## 要望
- 管理者（Kota）の権限で作ったタブだけを公開できる、タブ専用のストアを作る。
- 利用者は公開タブを保存して、自分のタブとして使えるようにする。

## 設計
- 置き場: アカウント用シートの kv に `store:tabs` として保存する（{tabs:[...], updatedAt}）。入口プログラム（Apps Script）に専用 op を追加する。
  - `storeget`: 認証なしで誰でも読める（公開タブの一覧取得）。
  - `storeset`: Google ログインのトークン必須。入口側でメールアドレスのハッシュが管理者のもの（account.js の ADMIN_EMAIL_HASH と同じ値）と一致した場合だけ書き込みを許可する。それ以外は 'not admin' で拒否する。
- 公開できるのは管理者だけ: サイト側でも、管理者モード（kgAdminOn）の端末にだけ、管理画面のタブ一覧へ「ストアに公開／公開中（取り消す）」ボタンを出す。二重の守り（表示制御＋入口側の照合）。
- 公開エントリ: {id, srcId（元のタブID）, name, artists, venues, organizers, fav, want, int, plan, oshiAll, intAll, publishedAt}。
- 利用者の保存: ストアのタブを自分のマイカレンダーへ複製する（新しいローカルID、fromStore にストア側IDを記録）。複製後は本人のタブとして自由に編集でき、ログイン中はアカウントにも同期される。同じストアタブの二重保存はしない（保存済み表示）。
- 表示場所: 管理画面（タブ・カレンダーの管理）内の「タブストア」節。タイムライン内管理からもそのまま使える。

## 運用
- 入口プログラムの差し替え（Code.gs の再デプロイ）が Kota の作業として必要。差し替え前はストア節に「読み込めませんでした」と出る。
- 公開の取り消しは storeset で配列から外す。利用者が保存済みの複製は残る（複製時点で本人のものになるため）。
