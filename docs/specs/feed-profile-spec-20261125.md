# フィードアプリのプロフィール反映 仕様（2026-11-25、Kota指摘「アーティストや会場データベースの情報がタイムライン・フィード側に反映されてません」への対応）

## 現状の診断
- データ自体は揃っている：シートの artists/venues タブには紹介文・公式リンク・メンバー・住所・アクセス・収容人数まで入っており、フィード側も v141 で同じプロフィールデータ（同梱データ＋シートのタブ）を読み込み済み。ただしフィードでは検索の照合にしか使われておらず、画面から見る手段がなかった。
- フィードのイベント詳細では、会場名・出演者・主催がすべて「ただの文字」で、タップしても何も起きない。これが「反映されていない」状態。
- タイムライン側はプロフィールシート（v90/v138）が存在し、カードのチップ・詳細モーダルから開ける。本仕様の対象はフィード側。タイムライン側の表示内容は実地確認で別途検証する。

## 実装（フィードアプリ）
1. 詳細シートの会場名・出演者（各名）・主催をタップ可能なチップにする。
2. チップをタップすると、詳細シートの上にプロフィールシートを開く（本体のプロフィールシートと同じ内容構成）：
   - カバー（会場はヘッダー画像があれば使用）＋アバター（アーティストはアイコン画像、なければ頭文字）
   - 名前、@ハンドル（X/InstagramのURLから）
   - 数字3点：掲載イベント／開催予定／3つ目は種別ごと（会場=カテゴリ数、アーティスト=出演会場数、主催=開催会場数）。中立な件数の事実表示のみ（順位づけ・人気表現はしない）
   - 推し／フォローボタン（本体と同じ保存先：推し=kg_trial_fav_performers_v1、会場・主催=kg_trial_follows_v1。本体と端末内で共有される）
   - タブ「スケジュール」：開催予定→終了の順にイベント行。行タップでそのイベントの詳細シートを開く。アーティストは所属グループ経由の公演も別見出しで出す
   - タブ「情報」：アーティスト=カテゴリ・読み・紹介文・公式リンク（公式サイト/X/Instagram/TikTok）・メンバー（役割・個別リンク付き）。会場=紹介文・住所・アクセス・収容人数・営業時間・施設種別・ジャンル分類・公式リンク・Googleマップ。主催=紹介文・リンク・次の開催。あわせて活動の傾向（主な活動エリア／よく出演する主催／共演／よく使う会場）を件数の事実として表示し、行タップで相手のプロフィールへ移動できる
   - プロフィールが未登録の名前でもシートは開き、スケジュールと「プロフィール未登録」の注記を出す（推測で埋めない）
3. 主催プロフィールもフィードで読む（シートの organizers タブを v141 の読み込みに追加）。
4. 閉じる（✕／戻る／背景タップ）で詳細シートに戻る。プロフィール同士の移動（共演・主催・会場の行タップ）はシート内で開き直す。

## やらないこと
- カード自体への名前タップ追加（スクロール操作と競合するため、入口は詳細シートに限る）
- 本体側の変更（タイムラインのプロフィールは実地確認の結果で判断）
- 人気・順位の表現、フォロワー数などの公開数値
