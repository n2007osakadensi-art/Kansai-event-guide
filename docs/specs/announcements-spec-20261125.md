# お知らせ配信（管理者だけが投稿できる更新情報）仕様（試作サイト v108、Kota 2026-11-25 13:13 指示）

## Kotaの判断
- 個人の投稿（v107で入れた「自分の投稿」）は不要。サイトが重くなりデータ量も
  増える方向なので撤去する。
- ただし「投稿できるのが管理者（Kota）だけ」という形は、全ユーザーへ更新情報を
  届ける手段として良い。この形で実装する。

## 仕組み
- 投稿デスクは、公開シートの「お知らせ」タブ。書き込めるのはシートの編集権限を
  持つ Kota と、Kota の指示で書く Muse だけ（＝管理者だけが投稿できる、が
  既存の権限の形で成立する）。
- 列: A=日時（YYYY-MM-DD HH:mm）／ B=タイトル ／ C=本文 ／ D=リンクURL（任意）
  ／ E=リンク文言（任意）。1行 = 1件のお知らせ。新しいものを上に追加していく。
- 表示側（試作サイトとフィード専用アプリ）は、このタブを読み取り専用で読み、
  新しい順に表示する。サイト側からタブへは書かない。
- 将来 Firestore が動けば、管理者モード内の投稿フォームから直接書ける形へ
  差し替え可能にする（表示側の読み込み口は1関数に寄せておく）。

## 表示（両面）
- 試作サイト: トップのバナー並びの先頭に、お知らせ帯を出す。最新1件のタイトル
  を表示し、未読なら NEW バッジ。タップで一覧（最大20件）を開き、開いた時点で
  既読にする（端末内に最終既読日時を保存: kg_notice_seen_v1）。
- フィード: ヘッダー（検索バーの下）に同じ帯を出し、タップで一覧シートを開く。
- お知らせが1件も無い／読み込めない場合は、帯自体を出さない（邪魔しない）。

## v107の撤去
- 「自分の投稿」の実装（マイページ内の投稿欄、端末内キー kg_trial_my_posts_v1、
  端末移行と同期への組み込み）を全て外す。既に誰かが書いた投稿データは端末内に
  残るが、表示・同期の対象からは外れる（キーは消さないのでデータ自体は消えない）。
