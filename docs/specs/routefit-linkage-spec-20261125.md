# 回せる現場 連動化 仕様（試作サイト v104、Kota 2026-11-25 10:28 指示）

## Kotaの指摘
「今から回せる現場を探す」が独立機能のままで、見ているイベントや回しプランと連動していない。
正しい形 = 見ているイベント／回しプランを起点に、移動と時刻表で判断して候補を提案し、
候補の時刻表その場で確認できること。

## 現状（2026-11-25 コード確認）
- 回せる現場ビュー（routefit）は起点を GPS／会場／「今日の全イベントのプルダウン」から選ぶ形。
  見ているイベントから直接起点にする入口が無い。プランとの連動も無い。
- 候補の時刻表は rfSlotNote の1行メモのみ。時刻表そのものは詳細を開かないと見られない。
- 既にある連動: プラン画面の「このあと回せる候補」（各日の最後の予定から最大3件、hopCandidates）、
  詳細の関連イベント「この日のはしご候補」。これらは残す。

## 実装（index.html のみ）
1. **詳細からの入口**: イベント詳細のボタン行に「このイベントの後で回せる現場」を追加
   （対象は当日のイベント）。押すとそのイベントを起点に routefit を開く。
   起点設定はプルダウンの e: 処理と共通化（rfSetOriginFromEvent）。
2. **プランの起点グループ**: 起点プルダウンの先頭に「今日の回しプラン」グループを追加
   （buildSlots の当日分、プラン順、♥/★付き）。
3. **既定の起点**: 起点未選択で routefit を開いたとき、当日のプランがあれば自動で起点を置く
   （開催中のプラン予定 → 次のプラン予定 → 最後のプラン予定 の順で選択）。
4. **次の予定への帰着判定**: 起点がプランの予定のとき、その次のプラン予定を求め、
   各候補について「候補の終了＋戻りの移動時間 ≦ 次の予定の開始」で判定し、
   行に「次の予定『タイトル』（HH:MM開始）までに戻れる見込み／間に合わない可能性」を出す。
   座標が無い組は判定しない（黙って落とさない）。
5. **時刻表インライン**: 候補行に時刻表（説明JSONの行）を最大8行まで小さく表示する。
   9行以上は「ほかN行（タップで詳細）」。行タップ→詳細モーダルは従来どおり。
6. **プラン画面からの入口**: プラン画面の当日グループに「この日のプランから回せる現場を全部見る」
   ボタンを追加（その日の最後のプラン予定を起点に routefit を開く）。

## 変えないもの
- 判定グループ分け（間に合う・途中から／開催中／距離不明／判定不可）と推定ラベル。
- 回し候補ボタンの配置ルール（カードには置かない）。
- 移動時間は推定のまま（実経路は Googleマップ／Yahoo!乗換リンクに委任）。

## 検証
- 構文チェック（全script）。
- 実サイト（公開後）: 詳細→起点、プラン→起点、次の予定の帰着判定、時刻表表示を確認。
