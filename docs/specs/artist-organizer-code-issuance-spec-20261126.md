# 仕様：アーティスト・主催者・会場アカウントの登録（Museメール受付＋コードをメール返信）

Kota指示（2026-11-26）：「まだ、アーティスト、主催者でアカウント作る仕組み作られてないと思うので会員コードの発行で対応と管理する仕組みを」
Kota追加指示（2026-11-26）：「登録はMuseメールに届いてコードをメールで返す仕組みで。アーティストや主催と紐付けも可能に。いるかわかりませんが、ライブハウスの人もアカウントを作れるように」

## 目的

アーティスト・主催者が自分でアカウントを作る仕組み（本人確認込みの自己登録フォーム）はまだ無い。当面の対応として、登録の申し込みを Muse メール（kansai-event-info@muse.ai）で受け付け、確認できたら会員コードを発行してメールで返す仕組みにする。対象はアーティスト・主催者に加えて、会場（ライブハウス等）の関係者も含める。

## 登録の流れ

1. **申し込み**：アーティスト・主催者・会場の関係者が、Muse メール（kansai-event-info@muse.ai）へ登録申し込みのメールを送る。申し込みには次を含む：名前（アーティスト名／団体名／会場名）、種別（アーティスト／主催者／会場）、返信先メールアドレス、公式SNSまたは公式サイト（本人確認用）、紐づけたいプロフィール（ガイドに掲載がある場合はその名前）。
2. **受付と確認**：届いた申し込みを Muse が受け付け、内容を確認する。本人確認はガイドの従来方針どおり、公式SNSとの連携で担保する（申し込み内容と公式SNS・公式サイトの情報が一致するかを見る）。判断に迷うもの、公式情報と一致しないものは発行せず保留にし、Kotaの判断を仰ぐ。
3. **発行と返信**：確認できたら会員コードを発行し、申し込みのメールへ返信する形でコードを送る。コードには種別と紐づけ先プロフィールを記録する。
4. **ログイン**：受け取った人は、通常の会員コードと同じ操作でログインできる。ログイン中は紐づけ先が分かる表示にする（例：「アーティスト ○○ としてログイン中」）。

## 紐づけ

- コード（アカウント）に、種別（アーティスト／主催者／会場）と紐づけ先を保持する。紐づけ先は、アーティストプロフィール（キー）、主催者プロフィール（名前）、会場プロフィール（キー）のいずれか。
- 保存先はアカウント用シート（関西イベントガイド アカウント同期）。通常の同期データと同じ場所に記録する。
- 紐づけは後から変更できる（プロフィールの統合・改名に追随できるように）。

## 管理

- 管理者モードの中に、発行済みコードの管理画面を置く。一覧で見られること：紐づけ先、種別、申し込みメールアドレス、発行日、状態（有効／無効）、最終ログイン（分かる範囲で）。
- 操作：無効化、再発行（再発行したら旧コードは無効。通常コードのルールと同じ）、紐づけ先の変更。
- 申し込みメールからではなく、管理者が直接発行する経路も残してよい（知り合いの出演者などにその場で渡す場合）。その場合も記録は同じ管理画面に載る。
- 閲覧者向けの通常コードはこの管理画面の対象にしない（従来どおり本人が発行する）。

## 権限について

- 現時点で、このコードに特別な編集権限は付けない。イベントの新規登録・修正は、従来どおりログイン必須の送信フォームから送り、取り込み側の確認を通る。
- 将来、自分のイベントや自分のプロフィールへの編集申請を紐づけ先に限定する拡張ができるよう、紐づけはデータとして保持しておく。

## 今回やらないこと

- サイト上の自己登録フォーム（申し込みはメールで受ける）。
- 役割ごとに使える機能を分ける本実装（閲覧者／アーティスト運営／主催者／会場／管理者の権限分け）。これは土台の後に別途設計する。
