# タイムライン×カレンダー共通タブ仕様（2026-11-28、Kota指示）

## 要望
- タイムラインに絞り込み設定済みのタブを複数持てるようにする（Xのリストのように管理・閲覧）。
- そのタブ設定でタイムラインとカレンダーを切り替えて見たい。
- 設定はカレンダーの絞り込み設定（マイカレンダー）と近しい形にする。
- 推しだけでなく「気になるアーティスト」も設定に含める。
- 設定に不足する対象は検索で探して追加できることを必須とする（現行の管理画面は推し・フォロー中からしか選べないのが不足）。

## 設計（既存のマイカレンダーを正本に統一）
- 絞り込み定義は既存のマイカレンダー（myCalendars / userdata.cals）を唯一の正本とする。新規の保存形式は作らない。
  - 定義 = {id, name, artists[], venues[], organizers[], fav, want, int, plan, oshiAll, intAll}
  - oshiAll（推し全員）と intAll（気になるアーティスト全員）は今回追加する動的ソース。calCustomKinds で判定する。
  - udMerge（account.js）の cals 統合に oshiAll/intAll の OR を追加する（同期で消えないように）。
- タイムライン: スコープ行にマイカレンダーをタブとして並べる（data-tlcal）。判定は calCustomKinds を共用。タブ選択中は「カレンダーで見る」ボタンを出し、カレンダー側はそのカレンダーを選択状態で開く。逆にカレンダー側（カスタム選択中）には「タイムラインで見る」ボタンを出し、タイムラインをそのタブで開く。スコープ行に「タブを管理」ボタンも置き、カレンダー管理画面へ遷移する。
- 管理画面（calMgr）の不足解消:
  - アーティスト候補 = 推し ∪ 気になるアーティスト ∪ プロフィール ∪ 全イベントの出演者。会場 = 会場プロフィール ∪ 全イベントの会場。主催者 = 主催者プロフィール ∪ 全イベントの主催者名。
  - 各セクションに検索欄を置き、検索時は全候補から絞り込む（未選択分は最大40件）。選択済みは常に先頭に表示する。
  - 編集中の選択は下書き（Set）で保持し、検索の再描画で選択が消えないようにする。保存は下書きから読む。
- 既存の固定スコープ（すべて／お気に入り／行きたい／気になる／回しプラン／フォロー中）とマイリストのスコープは従来どおり残す。タブとは排他。

## 受け入れ
- 管理画面で「気になるアーティスト全員」を含むカレンダーを作り、カレンダーとタイムラインの両方で同じ集合が見える。
- 推しでも気になるでもない出演者を検索で追加できる。
- 再読み込み・同期後もタブ（定義）が残る。
