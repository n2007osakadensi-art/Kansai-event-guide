# 編集機能をスペース版に寄せる作り直し仕様（2026-11-26、Kota決定）

## 発端
Kota: 「フォームじゃなくて新規登録と編集機能を実装してましたが使えませんでした。そもそもスペース版と全く別物に近いので使いにくすぎます」→ 作り直しを決定（2026-11-26 07:24）。

## 現状監査（2026-11-26、コード実物で確認）
既に揃っている部分（docs/editor-spec.md の正本仕様どおり実装済み）:
- セクション順は正本順と一致（種別→取り込み→画像→タイトル→日付→時刻→会場→出演者→カテゴリ→エリア→料金・チケット→公式リンク→撮影→詳細・タイムテーブル→主催→備考）
- 詳細画面からの「このイベントの修正を送る」（対象を読み込んだ状態で開く）、タイトル検索で対象を選ぶ読み込み
- 会場の正式キー候補（タップ選択）、画像プレビュー、タイムテーブルの行編集、送信バーの固定
- 送信経路は v163 で Google フォーム化し到達を実証済み。反映待ち表示は v162 で修正済み

残っている差分（今回直す対象）:
1. **カテゴリが自由テキスト**（主カテゴリ1欄＋追加・サブはテキストエリア）。スペース版は28種の固定分類からの選択式のはずで、自由入力は表記ゆれ・無効カテゴリの温床
2. **送信した後の状態が見えない**。送って終わりで、自分の送信がどうなったか（反映待ちか、反映されたか）を確認する画面が無い。「申請を投げた」感覚の正体
3. **取り込みが6時間ごと**で、送信→掲載の待ちが長い
4. **スマホでは46項目が1枚の長いダイアログ**に詰まっており、目的の節にたどり着くまで延々スクロールする

## 制約（変えられない前提）
- 試作サイトは静的ページ。正本はスペース版ガイドのままで、シートの events タブは同期で全件上書きされる。したがってサイトから本体へ直接保存はできず、「送信→取り込み登録→同期」の経路自体は維持する。寄せるのは項目・入力の形・状態の見え方・待ち時間

## 作り直しの内容
### A. カテゴリを選択式に（editor.js）
- 主カテゴリ: 28種のチップ単一選択（選択中のものだけ強調）。自由テキスト廃止
- 追加カテゴリ: 28種のチップ複数選択
- サブカテゴリ: サブを持つ親（スポーツ／ダンス／舞台・その他／お笑い／地域まつり）が主・追加のいずれかで選ばれているときだけ、その親の子をチップ複数選択で出す。保存形式は従来どおり「親/子」
- 読み込み時は既存値からチップ状態を復元する。payload の形（category／categories／subCategories）は変えない

### B. 節の折りたたみ（editor.js）
- 各セクション（h3）を見出しボタン化し、本文を開閉できるようにする。初期状態: 種別・タイトル・日付は開、その他は閉。「全て開く／全て閉じる」切替を上部に置く
- 修正の読み込み後は、値が入っている節は開いた状態にする
- DOM の id は一切変えない（既存ロジックを壊さない）

### C. 送信済み一覧（editor.js）
- 編集ダイアログ上部に「送信済み」ボタンを置き、自分の送信を一覧するパネルを出す
- イベント送信: 端末内の反映待ち記録から、タイトル・日付・種別・状態（反映待ち／反映済み）を表示。状態は現在の掲載データとの照合でその場に判定する（反映済み判定は v162 の pendingEditReflected／pendingReflectedIn を再利用）
- プロフィール送信: 送信時に記録を残し（kg_trial_submissions_v1）、「受付済み」として同じ一覧に出す
- 一覧から反映待ちを取り消せる（端末内表示の取り消し。受付側の送信は取り消せない旨を明記）

### D. プロフィール編集（profile-editor.js）
- アーティストのカテゴリを28種の選択式に変える（現在は自由テキスト）
- 送信時に C の送信記録へ残す

### E. 取り込みの高速化（cron kansai-editor-intake）
- 間隔を6時間→30分に変更
- 冒頭に軽い新着チェック（フォーム回答一覧＋メール一覧と台帳の差分）を置き、新着が無ければルールファイルを読まずに即終了する。新着がある回だけ、従来どおり5ファイル読み直し→処理に入る
- ジョブ名を「編集入力の自動取り込み（登録→シート同期まで）」に改める

## 完了条件（実地確認）
公開版で次を通す:
1. 詳細画面→修正→料金だけ変更→送信が即完了→再読み込み後も反映待ち表示が残る→送信済み一覧に「反映待ち」で出る
2. 取り込みを手動実行→登録と同期が済み、全端末向けの掲載にテスト変更が反映される→一覧の状態が「反映済み」に変わる→元に戻す送信も同じ経路で反映される（検証は終了済みの過去イベントで実施し、実データにテスト値を残さない）
3. 新規登録の送信→反映待ちとして一覧・タイムラインに出る→受付（フォーム回答）に完全な形で届いている
4. カテゴリのチップ選択で登録・修正ができ、読み込みで既存カテゴリがチップに復元される
