# 下部ナビゲーションバー仕様（2026-11-27、v218）

## Kotaの指摘
- 全ての画面において、トップページやタイムラインに戻るのが手間すぎる。
- Webサイトだがアプリ設計なので「戻るボタン」は入らない。その代わり、どちらへも簡単に戻れるようにしてほしい。

## 対応
- 画面下に固定のナビゲーションバー（#bnav）を常時表示する。構成は5つ:
  トップ／イベント／タイムライン／カレンダー／回しプラン（アイコン＋ラベルの縦並び、細身）。
- 現在表示中の画面に対応するボタンはアクセント色で示す。タイムラインを開いている間はタイムラインが点く。
- イベント詳細・アーティスト／会場データベース・特集など、どの画面からでも:
  - 「トップ」1タップでトップページへ（あわせて先頭へスクロール）。
  - 「タイムライン」1タップでタイムラインを開く。
- ボタンの動作は上部タブのクリックと同じ処理を通す（view-tab の click を呼ぶ）。タブ側の副作用（DB検索欄のクリア、プロフィール読み込み、保持中タイムラインの破棄など）をそのまま継承し、二重実装にしない。
- タイムラインは openTimeline() を直接呼ぶ。

## レイアウト上の配慮
- バーは画面幅いっぱい（PCでは本体カラム幅1180pxに中央寄せ）、z-index 60。タイムライン（120）、絞り込みパネル（85）、トースト（90）などのオーバーレイはバーの上に重なる。
- 本文（body）の下にバー高さ分の余白を確保し、末尾の内容がバーに隠れないようにする。
- 既存の右下フローティング「上へ戻る」ボタンは、バーの上に浮くよう bottom を引き上げる。
- safe-area-inset-bottom に対応（ホームインジケータと重ならない）。

## 対象外
- フィード専用アプリ（/feed/）は単一画面の設計のため対象外。本体側のバーのみ。
- オーバーレイ表示中（イベント詳細モーダル、タイムライン、絞り込み）は各オーバーレイ自身の閉じる操作が先で、閉じた直後にバーから1タップで移動できる（アプリの標準的な重なり順）。
