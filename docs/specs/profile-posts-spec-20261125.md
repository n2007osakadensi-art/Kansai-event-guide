# 自分のプロフィール＋投稿 仕様（試作サイト v107、Kota 2026-11-25 12:59 指示）

## Kotaの指摘
「テキストなどの投稿機能ないのにどうやって確認するの？未実装なら着手を」
SNS風の自分のプロフィールに、自分でテキスト投稿できて初めてプロフィールとして
確認・利用できる、という指摘。未実装部分に着手する。

## 前提（既存の整理と矛盾させない）
- プロフィールと投稿は端末内だけのもの。他人への公開・集計は一切しない
  （v106の注意書き「あなたの端末の中だけの表示です。他人に公開されることは
  ありません」を投稿にも適用する）。
- 保存は端末内データの流儀に合わせる: localStorage の新しいキー
  `kg_trial_my_posts_v1` に保存し、端末移行バックアップ（device-transfer）の
  対象に含める。既存キーは改名しない。
- フィード専用アプリとは同一オリジンなので localStorage を共有する。
  投稿データは将来フィード側プロフィールでも読める形にしておく
  （フィード側のプロフィール画面そのものは次段）。
- 新しい常設ナビゲーションは足さない。置き場所はタイムラインの
  マイページカード（v106）の中だけ。

## 実装（index.html のタイムライン内マイページ）
1. プロフィールカード内に「自分の投稿」欄を置く。
   - 投稿フォーム: テキスト入力（複数行）＋「投稿する」ボタン。
     空文は投稿できない。1件の上限は端末保存の常識的な範囲（例: 500字）。
   - 投稿一覧: 新しい順に表示。各投稿に日時を表示する。
   - 各投稿に「削除」ボタンを置き、その場で消せる（確認は簡易でよい）。
   - 投稿が0件のときは、空であることが分かる文言とフォームだけを出す。
2. 保存形式: [{id, text, ts}] の配列。id は時刻ベースの一意値。
3. 投稿したら即座に一覧と保存へ反映する（再読み込み不要）。
4. フィード表示モードのカード内に置く。スライド表示の細バーは従来どおり
   （件数表示を足すかどうかは任意、足すなら「投稿N件」）。

## 検証
- 構文チェック。公開後に実地確認: タイムラインを開く→マイページで
  テキストを投稿→一覧に出る→再読み込み後も残る→削除できる。
