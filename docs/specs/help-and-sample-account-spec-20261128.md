# 使い方説明とサンプルアカウントの仕様（Kota指示 2026-11-28）

目的: 説明なしで使えるのが一番だが、年齢や層を問わず誰でも分かる
取り扱い・機能の説明を用意する。あわせて「こんな感じで使えます」を
全員が見られるサンプルアカウントを作る。Kota本人がフォロー等をして
組み立てる。管理者モードとは別に運用できること。

## 1. 使い方ページ
- 画面名「使い方」。入口は (1) アカウント画面（ログイン欄の下）
  (2) フッター (3) サンプル表示の中。
- 文体: 短い文、専門用語を避ける、年齢を問わず読める平易な日本語。
  絵文字と番号で手順を示す。
- 章立て: このサイトについて／イベントの探し方／印の付け方
  （お気に入り・推し・気持ちの度合いの意味）／タイムライン／
  回しプラン／リストとマイタブ／ピックアップ（広告ではないこと）／
  ログインと同期（会員コードの扱い）／サンプルアカウント／
  お問い合わせ（kansai-event-info@muse.ai）。
- 掲載と更新について（Kota追加指示 2026-11-28）: 調べ方と掲載の
  進め方も利用者に伝える。ただし内部の詳しい仕組みは公開しない。
  伝えるのは「主催・会場・出演者の公式発表とチケット情報を照合して
  掲載している」「公式の情報が正本」「情報は段階的に発表されるので
  出たものから順に反映する」「当日の急な中止・変更は公式SNSのみの
  告知も多いので、出かける前に公式の確認を」「間違いは依頼フォーム
  から教えてほしい」という利用者向けの範囲に限る。更新反映への
  苦情にならないよう、仕組みとして淡々と書く（言い訳の文面に
  しない）。
- 静的な内容のみ。データに依存しない。

## 2. サンプルアカウント
- 通常の会員コードアカウントとして発行する（管理者ではない）。
  アカウント文書に sample: true を付け、所在は
  r:sha256('kg-sample-account:v1') のポインタで引けるようにする。
- 運用はKota: 自分のアカウントでログインしていないブラウザ／端末で
  サンプルコードでログインし、フォロー・推し・印・リスト・回し
  プラン等を組み立てる（自分のデータと混ざらないようにするため）。
- 公開表示はスナップショット方式: アカウントの現在データを書き出し
  sample/sample.json としてサイトに同梱し、誰でも読める見本表示
  （ショーケース）で見せる。書き出しはKotaの合図でMuseが行う。
  将来、入口プログラムの再デプロイ後はストア経由の即時反映に
  切り替え可能（store:sample）。
- 書き出しで絶対に含めないもの: 個人メモ（memos）、シグナル履歴
  （siglog）。含めるもの: お気に入り、推し、フォロー、気持ちの
  度合い、リスト、回しプラン、マイタブ、保存ワード、好み設定。
- 見本表示は読み取り専用: 見る人の端末データ・同期には一切触れない
  （localStorageへ書き込まない、インメモリで描画する）。
  中身はタイムライン型で、範囲は フォロー中／推しが出る／
  行きたい・気になる／お気に入り＋リスト・回しプラン・マイタブの
  一覧から各コレクションの中身表示。
