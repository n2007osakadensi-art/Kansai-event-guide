# データ辞書: 項目の定義と用語集

関西イベントガイドのデータが「どの項目に・何を・どの形式で」入るかの正本です。登録・修正・同期・表示のどの作業でも、項目の意味はここに合わせてください。掲載可否の判断は `docs/event-listing-rules.md`、調べ方は `docs/research-and-categories.md` が正本です。

## イベント（本体のレコード）

- `title`: イベント名。主催が公式に宣言した単一の正式名称そのまま（掲載ルール第2節）
- `date` / `dateEnd`: 開催日／終了日（期間開催のみ終了日を持つ）。日付は YYYY-MM-DD
- `timeLabel`: 開演・開始の表示文字列（例「14:00開演」）。確定していない場合は「未定」
- `startMin` / `endMin`: 開始・終了の分換算値（0時起点）。並び替えと「これから間に合う」判定に使う
- `venue`: 会場名。会場プロフィールのキー（正式名称＋市区町村のかっこ書き）で入れる。施設内ステージは分けず `venueSpaceNote` に書く
- `venueSpaceNote`: 会場内のスペース・ステージの補足
- 追加会場（回し・複数拠点）: 主会場のほかに巡回先・別拠点がある場合の経路情報。主会場の置き換えではない
- `area` / `prefecture`: エリア／府県（関西6府県: 大阪・京都・兵庫・滋賀・奈良・和歌山）
- `category` / `categories`: 主カテゴリ／カテゴリ配列（先頭が主）。カテゴリは28種のみ、複合文字列は書かない（研究ガイドのカテゴリ体系）
- `subCategories`: 階層サブカテゴリ。「親カテゴリ/子カテゴリ」の形で別項目に持つ
- `price`: 料金の表示文字列。チケット代のほかにドリンク代・手数料等の内訳が一次情報で分かれば含める
- `priceClass`: `free`／`paid`／`partial`（一部無料）のいずれか。不明は空。`isFree` は free のときだけ true（導出ルールは研究ガイド）
- `performers`: 出演者。名前だけを書く（時刻・説明・記号は入れない）。区切りは読点「、」
- タイムテーブル: 時刻順に並んだ構造化した表として別に持つ（出演者欄に時刻を書かない）。複数ステージは1レコードの中にステージごとの表を持つ
- `description`: 説明文。出典つきの事前告知（フライヤー画像内の文章等）から起こす場合はその旨が分かるようにする
- `linkWeb` / `linkTicket` / `linkX` / `linkInstagram`: 公式サイト／その公演自体のチケット販売ページ／公式X／公式Instagram。入れてよいのはイベントの公式・主催・会場・チケット販売だけ（出演者個人のSNSは入れない）
- `organizerName`: 主催者名。一次情報で判明したら必ず入れる（備考だけに書かない）
- 画像: 本体に保存した画像のキー群。公開URLは別管理（画像の全行程は `docs/workflow.md`）。1枚目が一覧・カードの代表画像になる
- テーマ・特別条件: ジャンルの補足（K-POP、キッズ、落語、公開収録等）や条件（コラボカフェ等）を表すタグ群。カテゴリの代わりには使わない
- 状態: 公開（published）が通常。中止は削除せず、タイトル先頭の中止表記＋備考に理由と告知元を書く

## シートのタブ（公開側のデータ）

シートはガイド本体からの同期で作られます。列の追加は末尾のみ（既存の列順は変えない）。

- `events`（26列）: id, title, date, dateEnd, timeLabel, startMin, endMin, venue, area, prefecture, category, categories（"|"区切り）, price, performers（"、"区切り）, description, linkWeb, linkTicket, linkX, linkInstagram, organizerName, imageUrl, venueSpaceNote, isFree, priceClass, views, impressions
- `events_lite`（19列）: 一覧表示用の軽量版。id, title, date, dateEnd, timeLabel, startMin, endMin, venue, area, prefecture, category, categories, price, imageUrl, venueSpaceNote, isFree, priceClass, views, impressions
- `events_details`（8列）: id, performers, description, linkWeb, linkTicket, linkX, linkInstagram, organizerName。サイトは lite を先に表示し、details を後から統合する
- `events_images`: id, imageCount, imageUrls（JSON配列）。画像が2枚以上あるイベントだけが行を持つ。配列の順序は本体の画像の並びと一致させる
- `artists` / `venues` / `readings`: プロフィールの同期タブ。サイトは読み込み時に同梱データへ統合する（自動反映）
- `検索辞書`: 正式名・種別（アーティスト／会場／イベント名／単語）・表記ゆれの語群・語の種別・出典（ガイド／クローラー管理／初期投入）
- `外部AI入力`: 他AIの調査結果の受け口。処理側が一次情報で再検証してから本体へ登録し、処理状況と処理メモを返す（手順は `docs/workflow.md`）
- 検索ログ系のタブ（会話パターン／未解釈ログ）: 検索の改善循環のための蓄積（後述）

## プロフィール

- **アーティスト**: 正式名称（現行の公式表記のみ）／読み／分類／メンバー（名前・役割・X・Instagram・アイコン）／別名（検索用の別名層。旧名・表記ゆれはこちらだけ）／公式リンク。出演条件（平日稼働・活動地域・出演料案件の可否＋根拠メモ・確認日）はガイド側だけの非公開情報で、公開タブには出さない
- **会場**: キーは正式名称＋市区町村。名称／読み／エリア・府県／ジャンル3段（大分類＞形態＞チェーン等の下位区分）／住所・アクセス／公式リンク／ヘッダー画像。閉館・改名しても削除せず、事実と時期を明記してアーカイブとして残す
- **主催者**: 主催者名を軸にイベントと結びつける。主催者別の表示と、イベントへの後付け登録ができることが前提（2026-11-25 対応開始）

## 検索辞書と改善の循環

- 辞書の役割: 表記ゆれ・読み・略記を正式名へ解決し、入力した文字列のままの検索を補う。検索そのものは辞書なしでも成立し、辞書は結果を歪めない
- 改善の循環: 検索ログ（特に解釈できなかった入力）をAIが後から読み、辞書・パターン・「もしかして」候補への追加を提案 → 検証 → 反映する。検索の実行自体はAIなし・トークン0のままで、AIは改善の後段だけに使う
- 略記の解決: 運営者や利用者の略記（例: EBIDAN）は、文脈と既存登録から公式表記（EBiDAN OSAKA）へ解決してから照合する。文字列の完全一致だけで「無い」と判断しない

## 用語集

- **正本**: スペース版ガイド（本体）。データの正はここにあり、公開面はその複製
- **面**: 表示・提供の場（本体／試作サイト／フィード専用アプリ／公開ミラー）
- **回し／はしご**: 同じ日に複数の現場を回ること。「回せる現場」は移動時間まで見て次に行ける候補を出す機能。「回し候補」ボタンは詳細の中だけ
- **推し**: お気に入りのアーティスト。端末内だけの個人情報で、公開・集計しない
- **反映待ち**: 送信フォームから送られ、端末内に保存されて表示へ統合される未登録データ。本体へ登録されるまでは本人の端末の中だけ
- **しおり**: 回しプランを共有用テキスト（AI向け／1枚画像向け／プレーン）に書き出す機能
- **動作記録**: サイト最下部の状態表示（版数と、前回停止した処理名）。版数の確認はここで行う
- **器**: 学祭・文化祭・地域まつり等の「主催行事そのもの」を指す分類上の概念。カテゴリ判断では器を優先する
- **特典会**: ライブ等に付随するサイン・チェキ等の特典対応。単独開催のみのものは掲載対象外（掲載ルール）
- **リリイベ**: リリースイベント（CD等の発売記念の店舗ライブ・特典会）
- **対バン**: 複数の出演者が共演するライブ形式
- **箱主催／貸館**: ライブハウスが主催する公演／会場を貸して外部主催が開く公演。主催の判定は公演ごとに確認する
- **一次情報**: 主催・会場・出演者・チケット販売の公式情報。まとめサイト等は一次情報ではない
